# Product Requirements — ETF Dashboard

**Version:** 1.0  
**Date:** 2026-09-26  
**Status:** approved (Step 3)

---

## Goal

A retail investor can find ETFs that fit simple rules (type, region, cost) and open one ETF to
understand it — without needing a brokerage account or financial expertise.

The experience is modelled on well-known ETF screener sites (justETF, ETF.com). Demo data only;
no live market data, no investment advice.

---

## Persona

**Retail investor, ETF-curious**

- Knows what an ETF is; not a quant.
- Wants to compare a handful of funds by cost and returns before researching further.
- Uses a phone first, then a desktop to read the details.
- Does not have an account; expects the page to just work.

---

## Features — v1 (MVP)

### F1 · Demo data

- ~40 ETFs generated by `scripts/generate-seed.mjs` with a fixed seed → `data/etfs.json`.
- Based on popular iShares fund names and tickers to feel familiar; not live data.
- Fields: ticker, name, issuer, asset class, region, currency, TER %, AUM, inception date,
  distribution policy, replication method, 1Y / 3Y / 5Y return, 1Y volatility,
  1 year of daily prices, top-10 holdings, sector weights, country weights.
- `lib/etf-repository.ts` exports `list(query)` and `getByTicker(ticker)`.
  The module validates the file shape with Zod on load; a corrupt file fails loudly.

### F2 · List page `/etfs`

- Route `/` redirects to `/etfs`.
- Table columns: ticker, name, issuer, asset class, region, TER %, AUM, 1Y return.
- Sort by any numeric column and by name (ascending / descending toggle).
- 20 rows per page; "Showing X–Y of N" count.
- Empty state with "clear filters" prompt (see Design).
- Disclaimer banner on every page: "Demo data — not investment advice".

### F3 · Filters and search

- Text search on ticker or name.
- Multi-select filters: asset class, region, issuer, distribution policy.
- Max TER slider / input.
- All filter, sort, and page state lives in the URL → every view is a shareable link.
- "Reset filters" button clears all params.
- Pure functions `filterEtfs()` and `sortEtfs()` in `lib/` with Vitest unit tests.

### F4 · Details page `/etfs/[ticker]`

- Header: name, ticker, issuer badge, asset class, region, distribution policy.
- KPI cards: TER, AUM, 1Y / 3Y / 5Y return, 1Y volatility, inception date.
- Price chart with 1M / 6M / 1Y range selector (Recharts).
- Top-10 holdings table.
- Sector weights bar chart; country weights bar chart.
- "Back to list" link preserves the filter/sort URL.
- Unknown ticker → styled 404 page.

---

## Quality bar (all features)

- Works from 375 px viewport; mobile-first layout.
- Every interactive element is keyboard-reachable; focus rings visible.
- WCAG 2.1 AA color contrast on all text and meaningful UI.
- Loading, empty, and not-found states handled for every data path.
- `pnpm check` green before any PR merges.
- Three Playwright e2e journeys:
  1. Filter by asset class → open a details page → back → filters still set.
  2. Copy the URL with filters applied → open it fresh → same view.
  3. Navigate to `/etfs/UNKNOWN` → 404 page shown.

## Out of scope — v1

| Item | Note |
|---|---|
| Favourites / watchlist | Requested by the user; moved to v2 (see below) |
| Portfolio / compare | v2 |
| Real market data / any external API | Never in this project |
| Authentication / accounts | v2 at earliest |
| Database | v2 at earliest |
| i18n | Out of scope |
| Deployment | Optional at the very end |

---

## v2 candidates (record of intent, not commitment)

- **Favourites:** user expressed interest during Step 3 interview. Implementation would need
  localStorage or a server-side store; left for v2 to avoid introducing auth or a database in v1.
- **Add ETFs via prompt:** seeded data can be extended by a natural-language prompt to the generator
  script; no UI change needed.
- **Compare 2–3 ETFs side by side** (already in v1.1 plan as `feat/10-…`).
- **Home overview with KPI tiles** (also v1.1 candidate).
